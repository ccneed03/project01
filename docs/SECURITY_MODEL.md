# 安全模型

## 信任边界

模型输出不可信。提示词、RAG 文本和工具返回内容都只作为数据处理，不能授予权限或直接执行写操作。

可信服务端负责：

- 当前用户身份；
- 订单归属；
- 参数结构；
- 政策版本；
- 硬性资格判断；
- 确认令牌；
- 写入状态机；
- 审计记录。

## 关键控制

### 身份与授权

- `user_id` 只从登录会话和 `AgentContext` 注入；
- 模型只能提供订单号，不能指定用户；
- 查询和写入都做订单归属校验；
- 越权查询统一返回“未找到该订单”，避免枚举。

### 确认协议

确认令牌是 HMAC-SHA256 签名，绑定：

- 动作 ID；
- 用户 ID；
- 会话 ID；
- 动作参数哈希；
- 过期时间。

令牌原文不落库。确认接口同时要求登录态、CSRF token、待确认状态、未过期和有效签名。

确认时重新执行资格判断，并比较预览快照。订单、商品、金额或政策变化会返回 `CONFIRMATION_STALE`。

### 写操作隔离

- 模型只能调用 `prepare_return`；
- `commit_return` 不在工具注册表中；
- 模型无法设置执行结果、退款状态或审批结果；
- 写入使用参数校验、条件状态更新和唯一幂等键。

### RAG 和提示注入

- 知识内容不包含可执行系统指令；
- 工具描述是静态白名单；
- 检索内容不能改变工具权限和用户身份；
- 政策结论以结构化规则表为准，文本只用于解释；
- 没有适用规则时必须失败关闭，不采用模型猜测。

### 数据最小化

- 订单查询不返回完整地址；
- 手机号只返回脱敏值；
- 工具审计参数应避免记录完整联系方式；
- 生产日志需要进一步配置 PII 脱敏和保留期限。

## 威胁与处理

| 威胁 | 当前处理 |
|---|---|
| 查询他人订单 | 服务端归属校验 + 模糊不存在响应 |
| 伪造确认 | HMAC 令牌 + 登录态 + CSRF |
| 重复点击 | 条件状态更新 + 幂等键 |
| 成功后重复确认 | 返回同一已保存结果，不再次执行写入 |
| 预览后被篡改 | 参数哈希 + 提交前复核 |
| 模型擅自承诺退款 | 提示词约束 + 最终状态只来自服务端 |
| 恶意文档提示注入 | 知识作为数据、工具白名单、规则表独立 |
| 过期政策 | 版本和生效日期 + 决策快照 |
| 工具循环 | 最大步数限制和失败转人工 |

## 生产环境必须补齐

- 单独的 `AGENT_ACTION_SECRET`，不得沿用公开默认值；
- HTTPS、安全 Cookie、密钥管理和轮换方案；
- 限流、账号锁定、审计告警和异常确认监控；
- 多租户数据隔离；
- PII 字段级加密、脱敏和保留策略；
- 真实人工转接和工单系统；
- 对账任务、补偿流程和退款系统边界；
- 安全测试、渗透测试和依赖漏洞扫描。
