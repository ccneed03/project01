# 产品范围

## 定位

> 售后智能服务 Agent：基于 RAG 的知识问答与受控退货申请。

用户在同一个对话中完成：

1. 询问售后政策；
2. 查询本人订单、物流和商品信息；
3. 补充商品状态与退货原因；
4. 获得确定性的资格判断和依据；
5. 预览并确认退货申请；
6. 获得退货申请编号和后续处理说明。

## 主用户

MVP 的主用户是消费者自助售后。客服工作台、坐席协同和批量售后不在当前范围。

## 核心边界

本项目解决“咨询和申请割裂”，不是完整的退款系统。

范围内：

- 售后政策解释与引用；
- 本人订单和物流查询；
- 商品目录查询；
- 7 天无理由退货资格判断；
- 质量问题转人工核验申请；
- 受控提交退货申请；
- 取消、过期、重复提交、越权访问处理。

范围外：

- 退款审批和打款；
- 换货、维修、补偿；
- 修改订单、取消订单；
- 库存查询；
- 批量退货和多订单合并；
- 自动审批质量问题；
- 客服坐席后台和跨渠道消息。

## 一条可验收旅程

```text
用户问“还能退吗”
  → 检索政策
  → 校验订单归属
  → 查询签收时间和商品
  → 追问是否拆封/使用
  → 规则引擎判断
  → 展示申请预览和政策版本
  → 用户确认
  → 服务端复核并提交
  → 返回申请编号
```

## 成功标准

- 政策回答有可定位的引用，不以模型记忆代替政策；
- 所有硬性资格条件由服务端规则判断；
- 未确认不写入，重复确认不重复写入；
- 确认后订单、商品状态或政策变化时，旧确认失效；
- 越权访问不暴露订单是否存在；
- 申请提交不表述为退款已经批准；
- 无法处理的请求能够带着上下文转人工。

## 当前演示假设

以下内容是可运行演示值，不代表真实业务已经确认：

- 默认退货窗口为签收后 7 天；
- 预计退款按 `unit_price × quantity` 计算；
- 未拆封原则适用于普通商品的非质量原因退货；
- 定制刻字商品和虚拟软件授权不支持无理由退货；
- 手机、笔记本和平板激活后不满足无理由退货条件；
- 质量原因在窗口内可以提交人工核验；
- 订单、物流和退货单均为本地演示数据；
- 人工转接目前只有提示和失败码，没有真实工单系统。
