# 后续需要补充的内容

## P0：进入正式演示或提交前

### 业务规则

- [ ] 由业务方确认退货窗口、起算时间、节假日和时区规则；
- [ ] 确认定制刻字、虚拟软件授权、手机/笔记本激活状态等品类的真实例外；
- [ ] 确认已拆封、已使用、破损的判定口径；
- [ ] 确认质量问题的受理窗口和人工核验流程；
- [ ] 确认预计退款金额是否等于实付金额，以及优惠、运费、积分如何处理；
- [ ] 确认政策版本和生效日期，并完成文本与规则表一致性签字。

当前 7 天、品类例外和金额公式是演示假设，需要业务确认。

### 数据与接口

- [ ] 提供真实订单字段和订单状态枚举；
- [ ] 提供物流服务接口、鉴权方式和超时约定；
- [ ] 提供商品目录及退货政策元数据；
- [ ] 提供退货申请接口和返回的申请状态；
- [ ] 提供人工工单或转接接口；
- [ ] 明确接口重试、幂等和错误码。

当前订单、物流和退货服务是本地模拟实现。

### 产品与合规

- [ ] 确认主用户是消费者还是客服坐席；
- [ ] 确认可提交不等于退款批准的文案；
- [ ] 确认确认卡片的必展示字段和用户协议；
- [ ] 确认人工转接 SLA 和服务时间；
- [ ] 确认数据保留期限、PII 范围和删除机制；
- [ ] 确认日志中允许保存的订单和联系方式字段。

### 运行配置

- [ ] 设置独立、高强度的 `AGENT_ACTION_SECRET`；
- [ ] 配置真实 `D_API_KEY`、`D_BASE_URL` 和支持 `tool_calls` 的模型；
- [ ] 在目标环境验证 Milvus、Ollama 或替换的检索服务；
- [ ] 执行 `python scripts/preflight.py --llm`；
- [ ] 完成至少一次全量演示彩排。

## 需要避免的误解

- RAG 文档不是资格判断的唯一真相源；
- 提交退货申请不是退款成功；
- 大模型说“已经确认”不等于用户点击确认；
- 一次数据库提交不能保证多个外部系统全局原子；
- 演示政策不能直接作为真实客服承诺。
